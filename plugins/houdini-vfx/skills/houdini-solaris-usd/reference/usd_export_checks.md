# USD Export and Restructure Checks

**Part of:** houdini-solaris-usd skill
**Loaded:** On-demand (progressive disclosure)
**Last Updated:** 2026-10-09

Three checks for USD that look fine in every measurement that only counts faces,
bounding boxes or binding targets. Each one was found by a render or an importer, not by
the verifier that should have caught it. Common principle: check what the CONSUMER sees
(what the renderer draws, what each face renders with), not the producer's bookkeeping.

---

## 1. Unreferenced points become a Points prim that Karma renders as spheres

**Rule:** before a render, traverse the stage Karma will render and list every gprim that
is not a Mesh, with its point count. Anything unexpected is a stop. Before export, count
the points no face references and delete them.

**Why:** meshes that were decimated or generated by another tool (an image-to-3D mesh
run through a decimator) keep points that no face uses. The asset file itself holds only
Mesh prims and looks clean. In Houdini those points are loose, and the SOP -> USD export
writes loose points as a separate Points prim (for example `.../asset/points_0`) with no
widths authored; Karma draws widthless points as large spheres. A clay render showed big
spheres over part of the scene and some item ids had zero pixels. Face counts and
bounding boxes were identical, because the loose points lay inside the mesh bounds, so a
verifier that counts faces or traverses Mesh prims only cannot see it.

```python
from pxr import Usd, UsdGeom

def non_mesh_gprims(stage):
    rows = []
    for prim in stage.Traverse(Usd.TraverseInstanceProxies()):
        if prim.IsA(UsdGeom.Gprim) and not prim.IsA(UsdGeom.Mesh):
            pts = UsdGeom.PointBased(prim).GetPointsAttr().Get() if prim.IsA(UsdGeom.PointBased) else None
            rows.append((str(prim.GetPath()), prim.GetTypeName(), None if pts is None else len(pts)))
    return rows        # clay/mesh-only render: expect []; Points / BasisCurves = STOP
```

Count unreferenced points per mesh, in the asset check and again in the export check:

```python
def unreferenced_points(mesh):                      # mesh: UsdGeom.Mesh
    npts = len(mesh.GetPointsAttr().Get() or [])
    used = set(mesh.GetFaceVertexIndicesAttr().Get() or [])
    return npts - len(used)                         # must be 0
```

In SOPs, remove them before the export (Clean SOP, remove unused points) and read back
`0` loose points on the geometry that goes into the USD ROP. The fix that worked on the
USD side was to rewrite the file keeping only face-referenced points and remapping the
vertex-interpolated normals and primvars; face count, size and pivot were unchanged.

## 2. Re-parenting a mesh must move its GeomSubsets WITH it

**Rule:** a `GeomSubset` must stay a child of the Mesh it subsets. When you re-parent or
rename a mesh at the Sdf level (for example wrapping it in a new Xform), move the
subsets with the mesh and lift only the non-subset children (materials scope, props).

**Why:** a restructure script copied the mesh spec to `/my_asset/my_asset_cloth` and then lifted
EVERY child of the old mesh up to the new Xform. The two `materialBind` subsets (front
print, back print) ended up at `/my_asset/material_0` and `/my_asset/material_1`, siblings of the
cloth, so they subset nothing, and the cloth's own binding was empty. The script's
self-check looked for binding relationships whose TARGET prim is missing, found none, and
passed. The material loss was invisible for a week because the other match checks were
geometric.

```python
# Sdf-level lift: skip subsets, they stay under the mesh
for child in old_mesh_spec.nameChildren:
    if child.typeName == "GeomSubset":
        continue
    move_to(new_xform_path, child)
```

**Verification - compute the bound material PER FACE, not the binding target:**

```python
from pxr import UsdGeom, UsdShade

def faces_without_material(prim):
    mesh = UsdGeom.Mesh(prim)
    nfaces = len(mesh.GetFaceVertexCountsAttr().Get() or [])
    mesh_mat = UsdShade.MaterialBindingAPI(prim).ComputeBoundMaterial()[0]
    covered, bad = set(), 0
    for sub in UsdGeom.Subset.GetAllGeomSubsets(UsdGeom.Imageable(prim)):
        idx = list(sub.GetIndicesAttr().Get() or [])
        covered.update(idx)
        if not UsdShade.MaterialBindingAPI(sub.GetPrim()).ComputeBoundMaterial()[0]:
            bad += len(idx)
    if not mesh_mat:
        bad += nfaces - len(covered)        # faces in no subset fall back to the mesh binding
    return bad

for prim in stage.Traverse():
    if prim.IsA(UsdGeom.Mesh) and faces_without_material(prim):
        print("NO MATERIAL on some faces:", prim.GetPath())     # any hit = FAIL
```

With orphaned subsets the mesh has no subsets and no binding, so every face counts as
unbound and the check fails loudly. Measured symptoms of the same fault: pxr
`ComputeBoundMaterial()` on the cloth returned None, and Blender's USD importer created
the cloth with zero material slots. Run the per-face check after ANY structural edit
(re-parent, rename, flatten, reference swap).

## 3. usd_rop savestyle: an invalid token fails silently

`savestyle` tokens are `flattenimplicitlayers`, `flattenalllayers`, `separate` and
`flattenstage`. An invalid token raises nothing and leaves a stub of about 700 bytes that
only references the SOP layer. Set the token, read `parm.evalAsString()` back, then open
the written file and count its prims (`len(list(stage.Traverse()))`); a tiny file with a
handful of prims and a sublayer reference is the stub.
